#Overview

Sightline has an MCP server built in. Any AI agent that speaks the Model Context Protocol, such as Claude Code, Claude Desktop, Codex or Cursor, can use it to take screenshots, read text on screen, mark up and style images, record and edit screencasts, and compare the screen with a design. The same tools also run from the terminal through sightline-cli.

The server runs on your Mac over stdio. It talks to the Sightline app, which does the work with its own permissions. Nothing goes over the network.

#Requirements

  • Sightline from the Mac App Store, on macOS 14 or later. Recording tools need macOS 15, a blur by subject and save_replay need macOS 27.
  • Sightline Pro, or the free 7 day trial. Agent access is a Pro feature.
  • Screen Recording permission for Sightline, in System Settings > Privacy & Security > Screen & System Audio Recording.
  • Agent access turned on in Sightline under Settings > AI Agents (Allow AI agents to use Sightline).
  • Sightline running. When it isn't, sightline-cli starts it for you.

#Connect a client

The quickest way: open Sightline, go to Settings > AI Agents, turn on agent access and click Connect next to Claude Code, Claude Desktop or Codex CLI. Sightline adds itself to that client's config. Start a new session in the client (or restart Claude Desktop) and the Sightline tools show up. Disconnect removes the entry again.

To set it up by hand, point your client at sightline-cli mcp as a stdio server:

#Claude Code

claude mcp add --scope user sightline -- \
  "/Applications/Sightline.app/Contents/MacOS/sightline-cli" mcp

Start a new Claude Code session afterwards. claude mcp list should show sightline.

#Claude Desktop

Add the sightline entry to mcpServers in ~/Library/Application Support/Claude/claude_desktop_config.json, then quit and reopen Claude Desktop.

{
  "mcpServers": {
    "sightline": {
      "command": "/Applications/Sightline.app/Contents/MacOS/sightline-cli",
      "args": ["mcp"]
    }
  }
}

#Codex CLI

Add this block to ~/.codex/config.toml and start a new Codex session.

[mcp_servers.sightline]
command = "/Applications/Sightline.app/Contents/MacOS/sightline-cli"
args = ["mcp"]

#Cursor and other clients

Any MCP client that can start a stdio server works. In Cursor, add the same entry as for Claude Desktop to ~/.cursor/mcp.json. Elsewhere, use this command and argument:

"/Applications/Sightline.app/Contents/MacOS/sightline-cli" mcp

#Command line

sightline-cli calls the same tools from a terminal or a script and prints the result as JSON. It lives inside the app:

/Applications/Sightline.app/Contents/MacOS/sightline-cli

Add an alias if you use it often:

alias sightline-cli='/Applications/Sightline.app/Contents/MacOS/sightline-cli'
# list every tool with its description
sightline-cli tools

# call one tool, prints JSON
sightline-cli capture_window --json '{"app": "Safari"}'
sightline-cli find_text --json '{"text": "Sign in", "window": {"app": "Safari"}}'

# show the usage
sightline-cli help
  • --json takes one JSON object with the tool's arguments. Leave it out for a tool without required arguments.
  • The CLI sets include_image to false unless you pass it, so the output stays readable.
  • On success it prints the result and exits with 0. On an error it prints the message to stderr and exits with 1.
  • The first call asks you to allow the terminal app in Sightline, like any new agent. Allowing a terminal also allows anything else you run in it.

#You stay in control

  • Off by default. Agents can't use Sightline until you turn on agent access in Settings > AI Agents.
  • Each agent asks first. The first request from a new agent opens a dialog with Deny, Allow Once, Allow This Session and Always Allow. Tick Limit to keep the grant to that one kind of action. Allowed agents are listed in Settings, where you can remove them, end session grants or clear the denied list.
  • You see every capture. Every agent capture plays the capture sound, and a notice names the agent and what it did. Recordings show a recording notice the whole time.
  • One folder. What agents save goes into the Agent folder inside your screenshots folder. Agents read and write only there, can't change settings and can't delete presets. Agent captures move to the Trash after 7 days, or the time you choose.
  • Credentials stay hidden. With Hide flagged credentials from agents on, text that looks like a password, key or token is blurred in images and left out of text results and search snippets.
  • Your recordings are safe. A recording you made is never overwritten. Agent recordings never include the microphone or the keys you pressed.

#Tool reference

23 tools. Every tool returns MCP content: JSON text, and for most image tools an inline image unless include_image is false. The examples show the arguments a client sends; with the CLI, pass the arguments object to --json.

#Capture

Screens, areas and windows are captured as PNG, JPEG or WebP into the Agent folder. Positions are in points with the origin at the top left of the main display, the same space list_windows and list_displays use. Images come back in pixels, so a Retina capture is twice as large.

#Edit and annotate

annotate changes a file and returns it. open_in_editor puts the same changes into the Sightline editor, where the user can adjust them before saving. Both take editor instead of a path to change a window the user already has open. Coordinates are image pixels with the origin at the top left.

#annotate

Draws marks onto a screenshot or recording, and crops, rotates, flips, resizes, styles or exports it. The recording options are under Recordings.

If the file is open in a Sightline editor, the change lands there live as one undo step. A screenshot the user saved with its edit is changed on its unedited original, with the user's marks kept.

ParameterTypeDefaultWhat it does
pathstringagent's last screenshotA file in the Agent folder, as a capture tool returned it, or a recording from last_recording.
editorstringAn id from list_editors, or front. The change goes live into that window as one undo step and no file is written.
annotationsarrayrequiredMarks to draw, in order. Pass [] to only crop, style or export. See annotation object.
cropobject{x, y, width, height} in pixels of the uncropped image, applied after drawing.
rotate90 180 270Turn a screenshot clockwise. Marks move with it.
fliphorizontal verticalMirror a screenshot, after rotate.
resizeobject{scale} from 0.05 to 1, or {width}, {height} or both in pixels. Only shrinks.
beautifyobjectSet a Style look, as in beautify.
exportobjectWrite a one-off copy: {format: png | jpeg | webp, quality: high | medium | small} for a screenshot. Never overwrites the source.
formatpng jpeg webpsource formatWrite the result to a new file in this format.
namestringWrite the result to a new file with this name.
outputstringFull path for the result inside the Agent folder; must not exist yet.
include_imagebooleantrueAttach a small inline preview. Set false when you only need the path.
{
  "tool": "annotate",
  "arguments": {
    "path": "~/Pictures/Screenshots/Agent/checkout.png",
    "annotations": [
      {"type": "arrow", "from": [200, 400], "to": [520, 260]},

#Recordings

Recording tools need macOS 15. Recordings are MP4. All seconds you pass, for marks, cuts, volumes, zooms and keys, count in the original recording, so a mark stays on its moment wherever its piece ends up.

#Editing a recording with annotate

Pass the path of an MP4 to annotate (or open_in_editor) and these options apply. Marks, blurs and the options below are drawn into every frame. The result is a new file; a recording the user made is never overwritten.

OptionTypeDefaultWhat it does
trimobject{start_second, end_second}: keep only this part.
piecesarray[{start_second, end_second, speed}]: the parts to keep, in play order. speed is 0.5, 1, 1.25, 1.5, 2, 4, 8 or 15; faster than 2x is silent.
soundarray[{start_second, end_second, volume}]: volume from 0 (muted) to 4.
zoomsarray[{start_second, end_second, x, y, width, height, transition, transition_seconds, follow}]. transition is smooth (default) or instant, transition_seconds 0.1 to 3 (0.5), follow is off, pointer or content. At most 6x.
zoom_on_clicksbooleanfalseAdd a 2x zoom for every click or group of clicks. Needs the pointer track.
pointerobject{shown, size: 1 | 1.5 | 2, hide_when_idle, click_highlight: off | ripple | ring, highlight_color}. Needs the pointer track; shown, size and hide_when_idle need a recording with the pointer left out (pointer: drawn).
keysobject{parts: [{start_second, end_second, mode: words | letters | shortcuts | hidden}], position: bottomLeft | bottomCenter | bottomRight | topCenter, size: small | medium | large, look: dark | light}. Needs a recording made with Show keystrokes on.
exportobject{size: original | 1080p | 720p, format: mp4 | mov, quality: high | medium | small}, or {format: gif, width: 160 to 1920 (640), fps: 1 to 30 (10)} for a looping GIF without sound.
{
  "tool": "annotate",
  "arguments": {
    "path": "~/Pictures/Screenshots/Agent/demo.mp4",
    "annotations": [
      {"type": "blur", "x": 820, "y": 40, "width": 300, "height": 44}
    ],
    "pieces": [
      {"start_second": 0, "end_second": 4},
      {"start_second": 4, "end_second": 12, "speed": 4}
    ],
    "zoom_on_clicks": true,
    "pointer": {"click_highlight": "ripple"},
    "export": {"format": "gif", "width": 960}
  }
}

Returns path, duration, width, height, has_sound, and under following any blur or zoom whose content was lost. No inline image for a recording.

#Working in the open editor

When the user says "this screenshot" or "the recording I have open", the agent doesn't need a file:

  1. Call list_editors. It lists the open editors, front window first, with an image of the front screenshot.
  2. To place a mark on text, call find_text with the same editor. It returns boxes in that picture's pixels.
  3. Call annotate, beautify or open_in_editor with editor set to the id, or front.
{
  "tool": "annotate",
  "arguments": {
    "editor": "front",
    "annotations": [
      {"type": "highlight", "x": 312, "y": 188, "width": 240, "height": 36}
    ]
  }
}

The change appears live and animated in that window, with the agent's name, as one undo step. No file is written; the user saves as usual. Recording editors take cuts, volumes, zooms, pointer and keys the same way. Ids stay the same while the window is open; an id that no longer exists returns no editor with that id is open; call list_editors.

#Recipes

Agents pick the tools themselves. These are prompts that work well:

Mark a bug

> Screenshot the Simulator, put a red box around the misaligned button and write "8 px off" next to it.

Blur before sharing

> Blur every API key on screen, then copy the screenshot so I can paste it into Slack.

Work on what I see

> In the screenshot I have open, number the three steps of the sign up form.

Find an old capture

> Find the screenshot with the invoice total from last week and open it in the editor.

Make a demo GIF

> Take my last recording, cut the first 3 seconds, speed up the loading part, zoom on every click and export a 960 px GIF.

Check against the design

> Compare the running app with signup-design.png and fix what differs.

  • The tools don't show up in the client. Start a new session, or restart Claude Desktop, after connecting. In Settings > AI Agents, a config that points to an older copy of Sightline shows an Update button.
  • record_screen stops early. It records at most 60 seconds per call. For longer screencasts, record from Sightline's menu and hand the file to the agent with last_recording.
