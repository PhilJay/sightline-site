#Overview

Sightline has an MCP server built in. Any AI agent that speaks the Model Context Protocol, such as Claude Code, Claude Desktop, Codex or Cursor, can use it to take screenshots, read text and codes on screen, mark up and style images, record and edit screencasts, find old captures and compare the screen with a design. The same 23 tools also run from the terminal, see Command line.

The server is sightline-cli mcp, a small program inside the app that speaks MCP over stdio. It hands every call to the running Sightline app over a local socket, and the app does the work with its own permissions. Nothing goes over the network.

#Requirements

  • Sightline from the Mac App Store on macOS 14 or later. Recording tools need macOS 15, a blur by subject and save_replay need macOS 27.
  • Sightline Pro, or the free 7 day trial. Agent access is a Pro feature; without it every call returns Sightline Pro is required for agent access.
  • Screen Recording permission for Sightline, in System Settings > Privacy & Security > Screen & System Audio Recording.
  • Allow AI agents to use Sightline turned on in Sightline under Settings > AI Agents. It is off until you turn it on.
  • Sightline running. When it isn't, sightline-cli starts it in the background and waits up to 8 seconds for it.

#Connect a client

The quickest way: open Sightline, go to Settings > AI Agents, turn on agent access and click Connect next to Claude Code, Claude Desktop or Codex CLI. Sightline offers three ways:

  • Connect automatically adds Sightline's entry to the client's config file. Because the App Store version can only change files you give it, the first time it asks you to choose the folder that holds the config (Grant access and connect).
  • Let your agent connect itself copies a short prompt. Paste it into a running agent session and the agent adds the entry.
  • Copy config copies the entry so you can paste it into the file yourself.

Then start a new session in the client, or quit and reopen Claude Desktop. Disconnect removes only Sightline's entry. When a config points to an older copy of Sightline, Settings shows Update.

To set it up by hand, point the client at sightline-cli mcp as a stdio server:

#Claude Code

claude mcp add --scope user sightline -- \
  "/Applications/Sightline.app/Contents/MacOS/sightline-cli" mcp

This is what Connect writes too: a sightline entry with type stdio under mcpServers in ~/.claude.json. Start a new session afterwards; claude mcp list shows sightline.

#Claude Desktop

Add the sightline entry to mcpServers in ~/Library/Application Support/Claude/claude_desktop_config.json, keep the other servers, then quit and reopen Claude Desktop.

{
  "mcpServers": {
    "sightline": {
      "command": "/Applications/Sightline.app/Contents/MacOS/sightline-cli",
      "args": ["mcp"]
    }
  }
}

#Codex CLI

Add this block to ~/.codex/config.toml, replacing an older [mcp_servers.sightline] block, and start a new Codex session.

[mcp_servers.sightline]
command = "/Applications/Sightline.app/Contents/MacOS/sightline-cli"
args = ["mcp"]

#Cursor and other clients

Any MCP client that can start a stdio server works. Cursor reads the same mcpServers entry as Claude Desktop from ~/.cursor/mcp.json. Elsewhere, use this command with the single argument mcp:

"/Applications/Sightline.app/Contents/MacOS/sightline-cli" mcp

The server announces itself as sightline with Sightline's version and protocol version 2025-06-18. It also sends one instruction to the agent: when the user talks about one of their own screenshots or recordings, call list_editors first and pass editor instead of copying files.

#Approval and safety

  • Off by default. Agents can't use Sightline until you turn on Allow AI agents to use Sightline.
  • Each agent asks first. Sightline identifies the program that started sightline-cli, such as Claude Code, Codex or Cursor, not the name a client reports. Its first request opens a dialog: Deny, Allow Once, Allow This Session or Always Allow. Tick Limit to ... to allow only that kind of action, such as window screenshots; unticked, the grant also covers the other screen actions.
  • Commands from a terminal are shown as coming from your Terminal, such as zsh. Allowing them for the session or always also allows anything else you run in that shell.
  • Manage grants in Settings > AI Agents: remove an allowed agent, End session grants, or Clear denied. Several denials in a short time stop new dialogs for a while (too many approval requests, try again later).
  • You notice every capture. Captures play the capture sound. With Show a notice when an agent uses Sightline on, the default, a banner names the agent and what it did. Recordings show a recording notice the whole time.
  • One folder. What agents save goes into the Agent folder inside your save folder, by default ~/Pictures/Screenshots/Agent. Tools only read files from there, plus the user recordings last_recording returns and pictures open in an editor. Agents can't change settings or delete presets.
  • Clean-up. Move agent captures to the Trash is After 7 days by default; you can choose Never, After 1 day or After 30 days.
  • Credentials. On Macs with Apple Intelligence, with Check captures for sensitive content and Hide flagged credentials from agents on, text that looks like a password, key or token is blurred in images an agent gets and left out of text results and search.
  • Your files stay yours. A recording you made is never overwritten; edits go to a new file. Agent recordings never include the microphone or the keys you pressed.

#Coordinates, files and seconds

#Points and pixels

Screen positions, such as area, pick_color and the frames from list_windows and list_displays, are points with the origin at the top left of the main display. Everything inside an image, such as annotation coordinates, crop, region and the boxes find_text returns, is pixels of that image with the origin at its top left. A capture's scale says how many pixels one point has, usually 2 on a Retina display.

Tools that take area, window or display accept only one of them. Leave all out to use the display under the pointer.

#Which files a tool takes

  • Every capture tool returns a path in the Agent folder. Pass it on to annotate, beautify, capture_text, copy_to_clipboard or open_in_editor.
  • Leave path out and those tools use this agent's last screenshot.
  • last_recording can return a recording the user made. That path works with inspect_recording, annotate, copy_to_clipboard and open_in_editor; results go to a new file.
  • search_captures returns the user's own files. Read them directly, or copy a screenshot into the Agent folder before annotating it. If it is open in an editor, pass editor instead.
  • Pass editor (from list_editors, or front) to work on what the user has open, without any file. See Working in the open editor.

#Seconds in recordings

All seconds you pass for a recording, for marks, pieces, trim, sound, zooms and keys parts, count in the original recording, before any cut or speed change. A mark at 12 s stays on what was at 12 s wherever its piece ends up, and disappears with a piece that is cut.

#Captures saved with their edit

With Keep saved captures editable on (the default), Sightline keeps the original of every capture the user edits. Tools then work on that original: open_in_editor and annotate restore the user's marks, crop, Style look, cuts, volumes, zooms, pointer and keys, and the result says restored_edit: true. Pixels and seconds then count in the original, turned the way the edit turned it.

#Tool reference

Every tool returns MCP content: a JSON text, and for most image tools an inline image unless include_image is false. Errors come back as a text with isError set. The examples show the tool name and the arguments object a client sends; with the CLI, pass that object to --json. Paths like /Users/you/... stand for real paths a tool returned.

#Capture

Captures are saved into the Agent folder in the format you pick and come back with path, width and height in pixels, scale, and an inline preview (with preview_width and preview_height) unless include_image is false. Whether Sightline's own windows, such as pins, appear in screen and area captures follows the Hide Sightline in captures and recordings setting.

#capture_screen

Takes a screenshot of a whole display, optionally with marks drawn on it.

ParameterTypeDefaultWhat it does
displayintegerdisplay under the pointerIndex from list_displays; 0 is the main display.
annotationsarrayMarks to draw before saving, in pixels of the capture. See annotation object. A blur by subject only works in annotate and open_in_editor.
formatpng jpeg webppngFile type. JPEG and lossy WebP use the quality from Sightline's settings. Transparent images stay PNG, and images over 16383 pixels are PNG instead of WebP.
namestringtimestampFile name without extension, such as login-error. A number is added when the name is taken.
include_imagebooleantrueAttach a downscaled inline preview. Set false to save tokens when only the path is needed.

The second display as a lossy WebP, without a preview, to keep the agent's context small:

{
  "tool": "capture_screen",
  "arguments": {
    "display": 1, "format": "webp", "name": "second-display",
    "include_image": false
  }
}

Returns path, width, height, scale and a preview.

#list_windows

Lists the windows on screen, front to back.

No parameters.

{"tool": "list_windows", "arguments": {}}

Returns An array of windows, each with id, app, title and the frame x, y, width, height in points.

#list_displays

Lists the connected displays.

No parameters.

{"tool": "list_displays", "arguments": {}}

Returns An array of displays, each with index (what display takes), name, the frame x, y, width, height in points, scale and is_main.

ParameterTypeDefaultWhat it does

#Edit and annotate

annotate changes a file and returns it. open_in_editor puts the same changes into the Sightline editor, where the user can adjust them before saving. Both, and beautify, take editor instead of a path to change a window the user already has open.

#annotate

Draws marks onto a screenshot or recording, and crops, rotates, flips, resizes, styles or exports it. Recording options are under Editing a recording.

If the file is open in a Sightline editor, also one the user opened, the change lands there live as one undo step. A capture the user saved with its edit is changed on its unedited original, with the user's marks kept.

ParameterTypeDefaultWhat it does
pathstringthis agent's last screenshotAn image or recording in the Agent folder, or a recording last_recording returned.
editorstringAn id from list_editors, or front. The change appears live in that window as one undo step and no file is written. Leave out path, output, name and export.
annotationsarrayrequiredMarks to draw, in order. Pass [] to only crop, style, resize or export. See annotation object.
cropobject or falseScreenshot: {x, y, width, height} in pixels of the uncropped image. Marks are drawn first, then the image is cropped. Recording: see Editing a recording.
rotate90 180 270Turn a screenshot clockwise. Marks and crop are given before the turn and move with it; text stays upright.
fliphorizontal verticalMirror a screenshot, after rotate. Text stays readable.
resizeobject{scale} from 0.05 to 1, {width} or {height} (the other side follows), or both (may stretch). Only shrinks, each side at least 16 pixels. Coordinates stay in the full size.
beautifyobjectA Style look: the fields of beautify except paths and output.
exportobjectA one-off copy, never over the source. Screenshot: {format: png | jpeg | webp, quality: high | medium | small}. Recording: see below.
formatpng jpeg webpsource formatWrite the result to a new file in this format.
namestringWrite the result to a new file with this name.
outputstringFull path for the result inside the Agent folder; it must not exist yet.
include_imagebooleantrueAttach a downscaled inline preview. Set false to save tokens when only the path is needed.

#open_in_editor

Opens a screenshot or recording in the Sightline editor, brings Sightline to the front and adds marks, a look, cuts or zooms the user can still change.

If the file is already open, no second window opens: the open window comes to the front and the change lands there as one undo step.

ParameterTypeDefaultWhat it does
pathstringthis agent's last screenshotAn image or recording in the Agent folder, or a recording last_recording returned.
editorstringAn id from list_editors, or front. The change appears live in that window as one undo step and no file is written. Leave out path, output, name and export.
from_clipboardbooleanOpen the picture on the user's clipboard instead of a file; leave out path. The picture is not returned to the agent.
annotationsarrayEditable marks to add.
beautifyobjectA Style look the user can change in the Style panel.
rotate, flip, resizeAs in annotate.
pieces, sound, zooms, zoom_on_clicks, crop, pointer, keysRecordings, as in Editing a recording. trim and export are annotate only.
include_imagebooleantrueWith editor and a screenshot: an image of the picture after the change.

Hand a capture to the user with suggestions they can move or delete:

{
  "tool": "open_in_editor",
  "arguments": {
    "path": "/Users/you/Pictures/Screenshots/Agent/onboarding.png",
    "annotations": [
      {
        "type": "highlight", "x": 210, "y": 404, "width": 520,
        "height": 48
      },
      {
        "type": "text", "x": 760, "y": 410, "text": "Shorter title?",
        "color": "#0A84FF", "size": 28
      }
    ],
    "beautify": {"look": "soft", "padding": 48}
  }
}

#Recordings

Recording tools need macOS 15. Recordings are MP4 in the codec of Sightline's Recording settings. A recording you made is never overwritten; annotate writes its result to a new file in the Agent folder.

#record_screen

Records a window, an area or a display for up to 60 seconds and notes where the pointer moves and clicks. Recording starts right away, so ask the user to get ready first.

A drawn pointer is not in the file itself, so pass the result through annotate before handing the file on. Keys are never noted for agent recordings, and the agent recording's pointer track goes with the Agent folder clean-up.

ParameterTypeDefaultWhat it does
secondsnumber 1 to 6010How long to record.
windowobject{app, title, id}: a case insensitive substring of the app name or window title, or a window id from list_windows. The frontmost match wins.
areaobject{x, y, width, height} in points.
displayintegerdisplay under the pointerIndex from list_displays; 0 is the main display.
include_audiobooleanfalseRecord system audio. The microphone is never recorded.
pointeroff video drawnvideodrawn leaves the pointer out of the file so Sightline can draw it later at any size, hidden while it rests. The default is off when the user's Pointer setting is off.
sizeoriginal 1080p 720poriginalScale the shorter side of a larger video down.
qualityhigh medium smallhighBit rate. Anything but the defaults encodes once more and keeps only the smaller file, with the pointer track scaled to fit.

#Editing a recording

Pass the path of an MP4 to annotate or open_in_editor and these options apply. Marks and blurs are drawn into every frame, or between their start_second and end_second. rotate, flip, resize, beautify and magnify marks are for screenshots only.

OptionTypeDefaultWhat it does
trimobject{start_second, end_second}: keep only this part. Use trim or pieces.
piecesarray[{start_second, end_second, speed}]: the parts to keep, in play order. Pieces must not overlap and last at least 0.1 s. speed is 0.5, 1, 1.25, 1.5, 2, 4, 8 or 15; up to 2x the sound keeps its pitch, faster is silent.
soundarray[{start_second, end_second, volume}]: volume from 0 (muted) over 1 (as recorded) to 4. Raised peaks are softly limited. Replaces a saved edit's volumes.
zoomsarray[{start_second, end_second, x, y, width, height, transition, transition_seconds, follow}]. The area fills the picture, widened to the video's shape; at most 6x. transition smooth (default) or instant, transition_seconds 0.1 to 3 (0.5), follow off, pointer or content. At least 0.2 s each, no overlaps. Replaces a saved edit's zooms.
zoom_on_clicksbooleanfalseAdd a 2x zoom for every left click or group of clicks: clicks less than 1.5 s apart and close together share one zoom, from 0.5 s before the first to 1.5 s after the last. Needs the pointer track.
cropobject or falseCut every frame to a rectangle: {x, y, width, height} in pixels of the original video, inside the video and at least 32 × 32; an odd size is rounded down to even pixels. Or {aspect: "16:9" | "4:3" | "1:1" | "9:16"} alone for the largest centered crop of that shape. false removes a crop, including the user's saved one; null counts as not given. A recording has a crop or zooms, not both: remove the zooms (zooms: []) or the crop first. Annotations, zooms and clicks keep counting in the uncropped video. The result reports the crop it used and width and height of the cropped video.
pointerobject{shown, size: 1 | 1.5 | 2, hide_when_idle, smooth, click_highlight: off | ripple | ring, highlight_color}. smooth (on by default) draws the pointer along a calmer path that still passes exactly through every click. Click highlights work with any pointer track; shown, size, hide_when_idle and smooth need a recording with the pointer left out (record_screen with pointer: drawn, or the user's Pointer setting Editable in the editor).
keysobject{parts: [{start_second, end_second, mode: words | letters | shortcuts | hidden}], position: bottomLeft | bottomCenter | bottomRight | topCenter, size: small | medium | large, look: dark | light}. Needs a recording made with Show keystrokes on. Defaults: bottomCenter, medium, dark.
exportobject{size: original | 1080p | 720p, format: mp4 | mov, quality: high | medium | small}, or {format: gif, width: 160 to 1920, fps: 1 to 30} for a GIF that loops forever, without sound (defaults 640 wide, 10 fps). A .mov or .gif result can't be edited again, so keep MP4 while more edits follow.

#Working in the open editor

When the user says "this screenshot" or "the recording I have open", the agent doesn't need a file:

  1. Call list_editors. It lists the open editors, front window first, with an image of the front screenshot.
  2. To place a mark exactly on text, call find_text with the same editor. It returns boxes in that picture's pixels.
  3. Call annotate, beautify or open_in_editor with editor set to the id, or front.
{"tool": "find_text", "arguments": {"text": "API key", "editor": "front"}}
{
  "tool": "annotate",
  "arguments": {
    "editor": "front",
    "annotations": [
      {
        "type": "blur", "x": 486, "y": 312, "width": 410, "height": 34,
        "edge": "soft"
      },
      {
        "type": "arrow", "from": [1100, 200], "to": [910, 318],
        "color": "#0A84FF"
      }
    ]
  }
}

The change appears live and animated in that window with the agent's name, as one undo step. No file is written; the user saves as usual. Recording editors take cuts, volumes, zooms, pointer and keys the same way. If the user is in the middle of an edit, the tool answers the user is editing this picture right now; try again in a moment. A closed window answers no editor with that id is open; call list_editors.

A file an agent changes that is open in an editor, also one the user opened, gets the change live in that window too, while the file is updated as well.

#Privacy

  • The MCP server runs on your Mac and talks to Sightline over a local socket that only Sightline's own signed CLI may use. Sightline sends nothing to the developer or anyone else and has no analytics.
  • Text recognition, subject detection, design comparison and credential checks run on the Mac.
  • Captures stay in your save folder. What happens to an image after an agent receives it is up to that agent and its provider.
